Check status:
  kubectl get pods -l app.kubernetes.io/instance={{ .Release.Name }}

Port-forward to try it locally:
  kubectl port-forward svc/{{ include "hn-crawler.fullname" . }} 8080:{{ .Values.service.port }}
  curl http://localhost:8080/health
  curl http://localhost:8080/entries?filter=long-titles

{{- if not .Values.persistence.enabled }}

NOTE: persistence.enabled is false — usage.sqlite lives on an emptyDir
volume. It survives Pod restarts but is lost if the Pod is rescheduled
to another node. Set persistence.enabled=true (with a StorageClass
your cluster provides) to back it with a PersistentVolumeClaim instead.
{{- end }}
{{- if gt (.Values.replicaCount | int) 1 }}

WARNING: replicaCount is {{ .Values.replicaCount }}, but usage.sqlite
is single-writer and lives on each Pod's own volume — each replica
will track a separate, unmerged usage history. Keep replicaCount at 1
unless usage tracking has been moved to a networked store.
{{- end }}
{{- if and .Values.autoscaling.enabled .Values.persistence.enabled }}

WARNING: autoscaling.enabled and persistence.enabled are both true.
Every replica would mount the same PersistentVolumeClaim and write to
the same usage.sqlite file concurrently — enable autoscaling only with
persistence.enabled=false (each replica then gets its own, siloed
emptyDir log) until usage tracking moves off SQLite.
{{- end }}
